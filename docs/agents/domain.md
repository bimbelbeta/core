# Domain docs

## Before exploring

Read the root `GLOSSARY.md` and any ADRs in `docs/adr/` that touch the area you're working in. If either is absent, proceed without suggesting it be created upfront. Domain documentation is created as terms and decisions are resolved.

## Layout

This repo uses a single-context layout: one root `GLOSSARY.md` and root `docs/adr/`.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues, proposals, hypotheses, and tests. If a concept is missing, reconsider the terminology or note the gap for domain modeling.

## ADR conflicts

Explicitly flag any output that contradicts an existing ADR rather than silently overriding it.
